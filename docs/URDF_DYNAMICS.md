# Native OSCBF URDF runtime dynamics

For the parameter provenance, mathematical explanation of the acceptance change
and limits of the hardware evidence, read
[model justification](cbf/URDF_MODEL_JUSTIFICATION.md). Agreement with OSCBF and
successful replay establish implementation consistency and numerical feasibility;
they do not establish physical calibration or conservative barrier predictions.

The arm runtime uses `UrdfPandaModel` for mass, Coriolis, gravity, joint-frame
kinematics and Jacobians. It no longer downloads or queries a libfranka model.
Libfranka remains the robot communication/control interface. The same current
URDF M/c values are supplied to every nominal law and to the optional CBF.

The base `config/panda_oscbf.urdf` is the exact asset from StanfordASL/oscbf
commit `6082329f8e1d61ee8e875a63a5cd80a14d513e12`. Its MIT license and asset
provenance are retained under `THIRD_PARTY_LICENSES`. No extra diagonal inertia
or fallback to libfranka dynamics is applied.

## Configuration and frames

The base model remains selectable with:

```yaml
controller:
  dynamics_model_file: package://teleop_controllers/config/panda_oscbf.urdf
```

The single- and dual-arm runtime YAMLs select
`package://teleop_controllers/config/panda_umi.urdf` in their shared controller
settings. The model adds two measured 5 g UMI attachments to the retained stock
fingers. Generic standalone control defaults to the base file. See
[finger integration and recorded avoidance checks](cbf/UMI_FINGERS_AND_OFFLINE_AVOIDANCE.md)
for transforms, estimated inertia, fixed-opening approximation and collision sweep.

An absolute file path is also supported. Per-arm
`arm_settings.<arm>.controller.dynamics_model_file` overrides work as for other
controller parameters. The file is read and validated once before control;
changing it requires restarting the owner. Startup logs and CBF diagnostics
identify `oscbf_urdf` and a fingerprint of the loaded file (explicitly FNV-1a-64,
not a cryptographic digest). There is no libfranka dynamics selection/fallback.

The parser requires the seven named Panda revolute joints in their canonical
chain and fixed attachment joints. Unknown/disconnected/duplicate chains,
unsupported moving fingers, malformed/nonfinite parameters and invalid inertia
are rejected before the robot connection. Visual meshes are not loaded.

Measured pose and previous torque still come from the same RobotState. The
reported `F_T_EE` supplies the actual configured tool-frame transform for the
last kinematic frame and its Jacobian. The fixed URDF attachment *inertial*
parameters remain those in the file. This preserves the existing end-effector
and table-geometry frame conventions rather than adopting the OSCBF demo's
different control-point offset. Mock tests retain their synthetic measured-pose
and control-Jacobian fixture, but use the same URDF M/c and CBF frame model.

Franka Desk's load metadata no longer changes our external dynamics model;
attachment mass/inertia/CoM edits belong in the URDF. The robot still performs
its own internal compensation. The runtime command remains gravity-compensated:
nominal laws add c where appropriate, and do not add g again. Published gravity
diagnostics now describe the active URDF gravity vector.

## Native calculation

Initialization loads the joint tree and link inertial parameters into bounded
fixed-size storage. It retains every fixed body's inertia, including nonzero
inertia on zero-mass bodies, exactly as the upstream asset/parser does. Fixed
bodies are evaluated individually; summing their kinetic energies is equivalent
to the upstream fixed-body merge.

For each current q/dq, forward recursion computes poses, axes and the angular/
linear accelerations at zero joint acceleration. The mass matrix is

`M = sum(m Jv.T Jv + Jw.T I_world Jw)`.

The Coriolis vector is the generalized inertial wrench at qdd=0, using each
body's CoM acceleration and `I_world*angular_acceleration + omega × I_world*omega`.
It matches OSCBF's automatic differentiation of the same mass matrix. Gravity
is `-sum(Jv.T * m * [0,0,-9.81])`, matching the base-level gravity convention of
their model. There are no finite differences, matrix derivatives approximated
across callbacks, Python/JAX calls, file I/O or allocations during evaluation.

All actuator clipping, input gates, CBF constraints/solver/slack policy,
synchronous/asynchronous execution, model-age checks and 600/800 us filter /
callback budgets retain their existing paths. CBF activation defaults and the
dual-arm hardware block remain unchanged. Controller-law selection remains
independent: both Cartesian laws consume this model.

## Verification

The committed reference fixture contains 64 states generated by unmodified
OSCBF/JAX 0.4.30 float64: 32 recorded states plus 32 deterministic random states.
The initial native comparison has maximum errors of 1.78e-15 in M, 1.56e-15 Nm
in c and 1.43e-14 Nm in g. Unit tests also check fixed zero-mass-body inertia,
tool-frame handling, invalid models/states and allocation-free evaluation.

Runtime regression, full recorded replay and single/dual mock timing evidence
are stored in `log/commissioning/2026-11-06-urdf-runtime/`. These are offline/mock
checks; no physical operation is part of this implementation. The preceding
[exact-model replay](cbf/OSCBF_MODEL_REPLAY.md) describes the numerical acceptance
evidence that motivated adopting this model.

The controller/bringup regression run passes **166 unique cases**, with zero
failures or skips. Evaluation performs no heap allocations in 1,000 calls.

Installed single/dual mock checks cover **20,079 callbacks** (9,001 active),
both Cartesian laws, shadow/filtered modes and forced native QP solving. Maximum
callback time is **388.808 us**, filter time **361.296 us**, and complete model
acquisition **17.273 us**. No deadline violations, diagnostic drops or process
faults occurred. These include calculating the URDF model inside every callback.

The installed native library also calculates M/c afresh for **30,445 recorded
active states**. Compared against the actual OSCBF outputs, maximum differences
are 3.11e-15 for M and 3.89e-16 Nm for c. Frame reconstruction differs from
recorded measured poses by at most 5.59e-10, and every recorded actuator-clipped
torque is reproduced exactly.

Every bounded nominal is mathematically feasible with the unchanged current
CBF for all three replay variants: recorded impedance nominal, recomputed
Cartesian impedance and recomputed inverse dynamics. The first two variants
accept and outgoing-verify **30,445/30,445** commands. Inverse dynamics accepts
**30,444/30,445**: one offline model-age guard event at cycle 27,357, with valid
rows and a feasible bounded nominal. That rejection is retained in the evidence
rather than counted as an accepted command. The unpaced batch replay is not
a callback timing qualification; the paced single/dual checks above exercise
that path under its actual deadlines.

The exact age-guard case passes all three nominal variants when replayed
individually with the same thresholds. Its original rejection remains in the
full-run count. All 47 CBF package files are byte-for-byte unchanged.
